Communication flows

Recall (read)

agent · scope memory.read
  • Agent asks a question through the bridge or POST /memory/recall.
  • Token resolves to an identity; memory.read scope checked.
  • BM25 ranks curated lanes over the persistent index.
  • Compact answer + source path:lines returned, secrets redacted.
  • Request logged to the hash-chained audit trail.

Suggest → promote (write)

agent suggests · operator promotes
  • Agent calls memory.suggest (memory.suggest scope).
  • Content lands in the pending lane — excluded from recall.
  • Agent cannot promote its own note — memory.promote is operator-only.
  • Operator reviews arvyx memory pending, then promote → notes lane.
  • Now recallable; author + promoter recorded in frontmatter.

Replication (backup)

backup host · scope replica.read
  • Backup calls /replica/manifest (sha256 per file).
  • Only changed files fetched via /replica/file; deletions propagate.
  • Control log + audit chain pulled via /replica/state.
  • Replica data may include token hashes; that does not grant writable failover authority.
  • Read-only recall is possible; manual, forced and automatic writable promotion remain refused without matching journal/effect authority.

Health & alerting

cron on both hosts
  • arvyx health probes HTTP, a recall smoke, and auth.
  • Verifies the local audit chain is intact.
  • Checks replica freshness against a max-age threshold.
  • Any failure → nonzero exit + alert on the ops bus.
  • Dashboard and bus-watching agents see the alert.
